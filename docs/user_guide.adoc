== Overview

This document explains how to use `sync-tools`, a **Go CLI wrapper** around rsync that provides advanced directory synchronization with .syncignore files, whitelist mode, filter layering, one-way/two-way sync, conflict preservation, and SyncFile post-sync actions.

The project has been fully migrated from Python to Go for better performance and single-binary distribution.

== CLI Commands

sync-tools provides two main commands:

=== sync command

The primary synchronization command with advanced options:

----
sync-tools sync --source SOURCE --dest DEST [OPTIONS]

# Basic one-way sync
sync-tools sync --source ~/documents --dest /backup/documents

# Two-way sync with dry-run
sync-tools sync --source ~/projects --dest remote:/backup/projects --mode two-way --dry-run

# Sync with filters and reports
sync-tools sync --source ~/data --dest /backup/data --ignore-src '*.tmp' --report sync-report.md
----

==== Options

- `--source`, `--dest` — Source and destination directories
- `--mode` — `one-way` (default) or `two-way` sync
- `--dry-run` — Preview changes without executing
- `--ignore-src PATTERN` — Exclude patterns from source
- `--ignore-dest PATTERN` — Exclude patterns from destination
- `--only PATTERN` — Whitelist mode (only sync matching patterns)
- `--use-source-gitignore` — Import .gitignore as exclusion patterns
- `--exclude-hidden-dirs` — Skip hidden directories (.git, .svn, etc.)
- `--report PATH` — Generate markdown report or patch file
- `--patch PATH` — Generate git patch instead of syncing
- `--apply-patch` — Apply generated patch with confirmation
- `--preview` — Show colored diff preview with paging
- `-y, --yes` — Auto-confirm operations
- `--interactive` — Two-phased sync with plan generation
- `-v, --verbose` — Increase verbosity

=== syncfile command

Execute declarative sync configurations using SyncFile format:

----
sync-tools syncfile SYNCFILE [OPTIONS]

# Execute a SyncFile
sync-tools syncfile MyBackup

# List available SyncFiles
sync-tools syncfile --list

# Dry-run a SyncFile
sync-tools syncfile MyBackup --dry-run
----

==== SyncFile Format

SyncFile uses Dockerfile-like syntax with post-sync actions:

----
# Variables
VAR PROJECT_ROOT=/home/user/projects
VAR BACKUP_ROOT=/backup

# Basic sync
SYNC ${PROJECT_ROOT}/docs ${BACKUP_ROOT}/docs
MODE one-way
DRYRUN false

# Filters
EXCLUDE .git/
EXCLUDE *.tmp
ONLY *.md

# Post-sync actions
APPEND config.yml:
  # Auto-generated footer
  generated_at: $(date)
END APPEND

PREPEND --backup README.md:
  # Project Documentation
  Last updated: $(date)
END PREPEND
----

== Filters and Patterns

sync-tools provides sophisticated filtering capabilities using rsync-compatible patterns:

=== Pattern Syntax

- `*` — Match any characters except `/`
- `?` — Match any single character except `/`
- `**` — Match any characters including `/` (recursive)
- `trailing /` — Match directories only
- `!pattern` — Explicit include (unignore)

=== Filter Types

==== .syncignore Files

Create `.syncignore` files in any directory to exclude patterns:

----
# .syncignore
*.tmp
*.log
.DS_Store
node_modules/
build/
----

==== Whitelist Mode

Use `--only` patterns to sync only matching files:

----
# Only sync markdown files
sync-tools sync --source docs/ --dest backup/docs --only '*.md'

# Only sync specific directories
sync-tools sync --source project/ --dest backup/ --only 'src/' --only 'docs/'
----

==== Gitignore Integration

Import `.gitignore` patterns as exclusions:

----
sync-tools sync --source project/ --dest backup/ --use-source-gitignore
----

=== Advanced Filtering Examples

----
# Exclude logs but include important.log
sync-tools sync --source app/ --dest backup/ --ignore-src '*.log' --ignore-src '!important.log'

# Sync only source code files
sync-tools sync --source project/ --dest backup/ --only '*.go' --only '*.js' --only '*.py'

# Complex patterns with recursion
sync-tools sync --source data/ --dest backup/ --ignore-src '**/temp/**' --ignore-src '**/*.tmp'
----
== Reports and Output

sync-tools provides multiple output formats for sync operations:

=== Markdown Reports

Generate comprehensive markdown reports:

----
sync-tools sync --source docs/ --dest backup/docs --report sync-report.md
----

Reports include:
- Configuration summary
- Statistics (files created/updated/deleted)
- Detailed change lists with file sizes
- Visual indicators for different change types

=== Git Patch Generation

Generate git patches instead of syncing:

----
# Generate patch file
sync-tools sync --source src/ --dest backup/ --patch changes.patch

# Preview changes with colored diff
sync-tools sync --source src/ --dest backup/ --preview

# Generate and apply patch with confirmation
sync-tools sync --source src/ --dest backup/ --patch changes.patch --apply-patch

# Auto-apply without confirmation
sync-tools sync --source src/ --dest backup/ --patch changes.patch --apply-patch -y
----

== Advanced Features

=== Interactive Mode

Two-phased sync with plan generation and editing:

----
sync-tools sync --source project/ --dest backup/ --interactive
----

This creates an editable plan file showing all operations, then allows you to:
- Review and modify the sync plan
- Exclude specific operations
- Apply conflict resolution strategies
- Execute the plan after editing

=== Two-Way Sync with Conflict Resolution

Bidirectional synchronization with automatic conflict handling:

----
sync-tools sync --source local/ --dest remote/ --mode two-way
----

Conflict resolution strategies:
- `newest-wins` — Use the most recently modified file (default)
- `largest-wins` — Use the larger file
- `source-wins` — Always prefer source
- `dest-wins` — Always prefer destination
- `backup` — Create backups before resolving

== Troubleshooting

=== Common Issues

**Build Issues:**
----
# Verify Go version (requires 1.19+)
go version

# Clear module cache if needed
go clean -modcache && go mod tidy

# Rebuild
go build -o sync-tools ./cmd/sync-tools
----

**Test Failures:**
----
# Run specific test suite
go test ./test/bdd -tags bdd -run 'BasicSync'

# Verbose output for debugging
go test ./test/bdd -tags bdd -v -run 'APPEND'
----

**Runtime Issues:**
- Ensure rsync is installed and accessible (`rsync --version`)
- Check file permissions on source and destination directories
- Use `--dry-run` to preview operations before execution
- Enable verbose logging with `-v` for detailed output
